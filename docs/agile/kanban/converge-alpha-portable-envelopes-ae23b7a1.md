## Unresolved owner decision

Issue #51's original requirement that doubles fail remains unchanged. The
merged upstream `portable-integer?` accepts finite integral JVM `Double` values,
including `1.0`, while JavaScript uses one numeric representation for `1` and
`1.0`. A shared name alone does not establish identical identity semantics.
An explicit owner-authorized decision must reconcile Alpha identity admission
with this accepted boundary before code or a dependency update. Distinguish
portable payload numbers from Alpha identity values; do not silently weaken
issue #51, copy the upstream grammar, or create another portability kernel.
