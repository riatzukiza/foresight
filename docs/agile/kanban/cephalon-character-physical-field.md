## Context

Fork Tales' February 20 corrections describe flexible nexus bonds, sparse
deposited winds, moving particles and immutable emitted ownership. Historical
Eidolon tension gradients, deterministic nexus walks and OpenPlanner cost fills
are related recovery strata with different mechanics. They cannot be equated by
shared names. The operator explicitly requires the physical graph to work.

## Outcome

One reviewed physical graph/field computation changes actual associative recall.
Its state and causal trace survive restart and reproduce under replay.

## Scope

Recover portable pure laws from the actual Fork Tales implementation and later
corrections, establish their mapping to OpenPlanner's graph/field seams, and
consume them from Knoxx. OpenPlanner owns its existing graph persistence/query
surface; Knoxx owns product integration. Planning review must name the owning
kernel/library and numeric representation before code admission. Use `.cljc`
where practical and keep runtime-specific adapters outward. No automatic
promotion into Foresight common law or parallel Python effect runtime.

## Non-goals

Ship only a force-layout visualization, rename vector search as physics, keep
two competing edge-force engines, infer usefulness from retrieval counts, or
copy the entire experimental runtime with its infrastructure.

## Acceptance criteria

1. An explicit source-to-law mapping covers positions/velocities, semantic
   attraction, mass/friction, elastic nexus bonds, sparse field deposit/decay,
   bounded seeded exploration, collision/absorption/deflection and intent
   exchange. Any unsupported mechanic remains a blocking gap for this outcome.
2. Presences, nexus and daimoi have the corrected differing friction; nexus
   do not acquire self-propulsion. Dissimilar intent can produce a flexible
   long-range bond. Presentation coordinates cannot substitute for physical state.
3. Moving entities sample and alter local fields; deposits influence later
   motion and memory traversal. Decay uses actual elapsed time. Test both quiet
   time and repeated ingestion at the same timestamp.
4. Emitted daimoi ownership is immutable. Seed, mantle and intent lineage remain
   attributable through exchanges/collisions; the older owner-handoff proposal
   cannot silently override the later correction.
5. Stable content embeddings coexist with versioned context/field salience.
   State changes do not rewrite canonical memory or re-embed unchanged content.
6. Changing a deposit or bond under a fixed seed changes a resulting recall path
   and included association. A disconnected simulation or increased trail count
   with no cognitive effect fails this criterion.
7. Identical event order, initial state, timestep schedule, solver/config revision
   and seed replay within a declared numeric tolerance. Nonfinite values,
   pathological time steps, conflicting owners and exceeded resource bounds are
   refused explicitly; restart reproduces the same state/revision.
8. Reinforcement is attributed to outcomes; repeated retrieval alone cannot
   establish useful recall. Permission checks apply to traversal and feedback.

## Verification

Red portable law/property tests exercise actual coupling and replay, followed
by owning graph adapter tests and the Knoxx context seam. Retain source commits,
hashes, seeds, timestep schedules and traces. Run both host representations if
the selected kernel crosses runtimes; declare numeric tolerance before results.

## Risks

Non-equivalent historical models, numeric instability, embedding revisions,
global graph costs, feedback saturation, hidden private paths and unclear kernel
ownership. Eight points is provisional and must split if recovery reveals more
than one independently reviewable kernel change.
