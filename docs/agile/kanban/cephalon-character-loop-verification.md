## Context

Existing successful creations, vector hits, graph metadata, candidate images and
HTTP health do not verify the complete character loop. The active maker must
keep working during review and preparation. Deployment needs the existing
reserved head, terminal ownership/fencing, publication and lifecycle guarantees.

## Outcome

A reproducible verification path proves the entire loop on qualified revisions,
then a bounded live sequence demonstrates the same causal relationships and
independently observed outcomes with one event consumer owner.

## Scope

Cross-repository revision-bound fixtures and human runnable verification,
deployment/rollback proof for affected services/contracts, and natural clock
observation. Keep original identity, timestamps, images, contract hashes,
seeds, artifact hashes, graph paths and publication/outcome IDs inspectable.

## Non-goals

Complete the epic with a small vector/transport test, claim novelty from changed
adjectives, reset history, restart active makers, move cloud event ownership, or
waive native Rheos/canonical review and production qualification.

## Acceptance criteria

1. Isolated scenarios prove each full link: admitted outside event -> physical
   graph/field update -> separate mood/attention -> authorized traced recall ->
   creative/social choice -> verified outcome -> memory/relationship update.
2. Under fixed seed/config, paired different encounters change an actual
   association and choice. Replay with identical input recovers the same state
   and trace within declared tolerance. Missing links explicitly fail.
3. Restart, concurrent facets, delayed/out-of-order observations, denied memory,
   graph/appraisal failure, unknown social effects and context pruning retain
   truthful state and immutable provenance. Failed effects do not count as work.
4. While maker/intake/graph/appraisal lanes are saturated, the reserved head
   acknowledges and none of the held maker identities is aborted or replaced.
   Terminal parent/delegate/effect ownership is proven before recovery.
5. Exact tested candidate revisions, current personal review/base bindings,
   native lawful predecessor readiness and independent deployment gates all
   pass before affected production services/contracts are changed. Candidate
   readiness does not enable a second clock/gateway consumer.
6. After qualified idle/fenced deployment, natural clock opportunities show
   changing outside context, recalled association and choice; saved artifacts
   and actual social/destination results are independently inspected. Report
   quality/variety limits separately from transport and tool completion.

## Verification

The script verifies served revisions and credentials/scope prerequisites first,
creates and cleans only owned isolated fixtures, exits nonzero for broken links,
and names explicit warnings for unverified availability/quality. Live observation
never replays an existing post or interrupts a maker. Completion requires the
whole epic audit, not a locally passing subset.

## Risks

Different repositories serving different revisions, unqualified parent review,
missing native dependency admission, flaky remote APIs and artistic claims that
automated causal tests cannot establish alone.
