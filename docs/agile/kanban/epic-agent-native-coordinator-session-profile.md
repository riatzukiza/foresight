# EPIC: Reconcile the agent-native coordinator-session profile

## Context

[Foresight issue77](https://github.com/open-hax/foresight/issues/77) requests a
portable contract language and an abstract coordinator-session proof. Original
[PR78 at 0c0fcab33c7a2b685a0ecf5ff6138a3173e0a31e](https://github.com/open-hax/foresight/tree/0c0fcab33c7a2b685a0ecf5ff6138a3173e0a31e/docs/specs)
contains four proposal artifacts and an unestimated fourteen-workstream task.
Its predecessor UUID is `8b4c1abb-6599-4bdf-a2aa-2adeec62e821`, recorded as
accepted in that source branch. That card is absent from this base; this is a
body provenance reference, not a parent or a copied state transition.

[Personal PR9 at 91a02f8547cda726bea30c288e4df5aa1db899b2](https://github.com/riatzukiza/foresight/pull/9)
already plans causal event graphs and bounded authority in CS1.02
(`preserve-raw-causal-event-graph`) and CS1.06
(`purpose-roles-bounded-authority`). Those are overlap references, not hard
prerequisites or accepted common law. PR9 does not specify the closed six-form
session profile or structured child-session result. Its research, simulation,
multiresolution projection and devtools stories need no duplicate plan here.

The base is personal synchronization PR3 at
`96a6dca24cb7a14b041bdd6e3e7922c568238da9`, preserving accepted root source
`fcfc2d17f28640203066ddfe0a22f87db7372a32`. Child evidence controls its local
contract; root routing metadata alone does not confer ownership or promotion.

## Outcome

Reviewers can assess one bounded session composition profile and route each
remaining implementation obligation to its canonical owner without importing
PR78 wholesale or making Foresight a second contract or event kernel.

## Scope

Two planning stories, totaling five points (2 + 3):

- ANW1.01, `63b6320a-a4fb-43c4-9923-e5e8e970ca1d`: a pinned owner-seam
  crosswalk for six forms and their referenced session/event/receipt/authority
  contracts, 2 points; no prerequisite.
- ANW1.02, `1889fdc5-87f0-40d5-a02c-39cc7abf1498`: a closed coordinator
  fixture and form/failure obligations consuming ANW1.01, 3 points.

Five is the child sum, not a second estimate or an estimate of all issue77.
The stories produce reviewed specification and fixture descriptions. Separate
owner-repository implementation cards must follow before executable claims.

## Non-goals

Implementing an interpreter, schema engine, resolver, prompt renderer, ledger,
Rheos semantics, identity service, Python/pickle adapter or live agent session;
reassigning ownership; accepting cross-repository law; rewriting original78;
copying its established status; changing other cards; deployment or services.

## Acceptance criteria

- [ ] Every proposed form names its existing owner seam or a specifically
  evidenced gap, with full revision and path provenance.
- [ ] Old proposed shapes are compared explicitly against current contracts;
  incompatibilities are neither hidden nor silently normalized.
- [ ] CS1.02/CS1.06 overlap is referenced without duplicating their causal
  graph or bounded authority implementation outcomes.
- [ ] One coordinator fixture covers two resources, two narrowed child
  contexts, structured child results, one artifact and deterministic replay.
- [ ] Every deferred issue77 workstream remains visible as unestimated
  follow-up scope; this epic does not claim the whole issue complete.
- [ ] Planning review and a lawful Rheos ready transition precede any story
  execution; incoming Markdown is not board admission evidence.

## Verification

Review the full three-card diff, child-sum estimate, sibling relationships,
source revisions and semantic overlap. Planning PR publication also runs the
existing root project validation and immutable receipt consumer against its
full base/head. Those checks do not validate board lifecycle. Rheos alone owns
operational board admission, comments and transitions. Native planning review
and required hosted gates must qualify the current head before readiness.

## Risks

The original proposal predates extracted child ownership. Reusing names without
checking actual contracts could duplicate Clio or Katamorph. Planning snapshots
may change before implementation: refresh each owner seam then preserve both
old and new evidence. Required acceptance of common law remains subject to
[project-law promotion triage](../../notes/project-law-promotion-status-triage.md),
not the merge of this planning PR. Provider review quota cannot supply approval.

## Remaining issue77 scope

Grammar/normalized AST and primitive floor; schema subset beyond demonstrated
existing contracts; other kernel shapes; runtime and codec/version negotiation;
Python reference adapter; prompt compiler and target profiles; executable
cross-host conformance and the full coordinator proof remain separately
estimated follow-ups after this profile is reviewed. Portable semantics should
remain pure Clojure data/.cljc where practical; the explicitly requested Python
reference runtime remains a later adapter decision, not silently discarded.
