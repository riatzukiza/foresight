# Qualify synchronization review boundaries before advancing the personal stack

## Context

[Personal Foresight PR3](https://github.com/riatzukiza/foresight/pull/3) preserves
both the personal fork's accepted development-origin law and accepted origin
history. At head `96a6dca24cb7a14b041bdd6e3e7922c568238da9`, CodeRabbit raised
17 native findings: 15 concern recovered `clobber` input and two concern root
documentation. MiMo supplied an exact-head approval; canonical admission still
reports unresolved findings and zero completed code rounds.

## Outcome

Settle every synchronization finding with verified scope and canonical evidence,
repair the two current root documentation discrepancies, and advance the shared
base only through qualified integration. Preserve recovery evidence and bounded
development diffs while the other lanes remain independently reviewable.

## Scope

- Assess every recovered-input request against `clobber/PROVENANCE.md`, root
  inventory-only execution law, the archived source and the extraction owner.
  Request an independent assessment rather than treating provenance as assent.
- Catalog the four newly confirmed recovered-note/sample defects in root-owned
  provenance without rewriting their source: RPC field disagreement, immediate
  result/synchronous-throw handling, literal environment placeholders and missing
  extracted reference definitions. Preserve the correct `.pm2.cljs` dispatch
  distinction; only the `.pm2.clj` compound suffix misses its evaluation branch.
- Correct README's execution-refusal sentence to include `clobber`, and append
  the later immutable caller revision to the migration acceptance history without
  assigning PR121's historical results to that later revision.
- Publish any proposed boundary decision with the actual head, native finding
  IDs, evidence and independently identified assessment. Preserve the distinction
  between a local agent assessment and authenticated native rejection evidence.
- Before changing the shared synchronization branch, read back all dependent
  heads and bases and retain their exact previously tested candidates. Qualify
  each affected new base/candidate through the owning canonical gate; a stable
  PR head alone does not preserve tested-merge evidence after a base change.

## Non-goals

No donor runtime repair, generated bundle rebuild/deletion, process execution,
credential substitution, recovered example rewrite, automatic rejection, copied
Bot identity, native approval fabrication, history rewrite, board-state parser,
protection change, automatic merge or deployment activation. The synchronization
branch and dependent PR heads are unchanged by this planning input.

## Acceptance criteria

- Each of the 17 native findings has a specific verified disposition; concerns
  still lacking admissible corroboration remain open and explicitly blocked.
- Root documentation matches the actual execution refusal and immutable caller
  pin, while prior revision-specific observations remain preserved. The October3
  restoration paragraph remains historically true; add the later functional
  repair observation rather than correcting that historical event.
- Recovered source/design records retain inspectable provenance; any proposed
  change of preservation policy is explicitly reviewed rather than inferred from
  a synchronization review or from the mere existence of a defect.
- Required deterministic checks and review evidence bind the actual head, base
  and tested merge candidate after qualified integration; no other lane borrows
  an approval or an earlier-base result.
- Planning findings are settled and Rheos lawfully admits ready before new
  implementation; final origin publication remains a separate release/deploy PR.

## Risks

Source-preserving synchronization can expose defects already accepted as
recovery evidence. Repairing that runtime silently would change the preservation
contract; rejecting every request merely because it is old would hide valid root
documentation defects. Updating a shared base also changes tested candidates
without changing the dependent heads. Treat each distinction explicitly.
