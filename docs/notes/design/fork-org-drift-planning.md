## Explicit target distinction and protected proof binding

Existing `pr-flow-promotion` AC2 requires org/main ancestry of the qualified receipt-bound feature X; it also expressly forbids substituting a later fork-main tip for delayed X. The workspace drift outcome instead compares org/main to current fork/main. These are distinct queries over the shared pure contract: its caller supplies an explicit target SHA/purpose, and provenance binds which target was checked. Before promotion, the owner must preserve both the fresh workspace drift obligation and the receipt-X-specific prerequisite. The proposed typed query records source identity, mapped pair/network, ref kind, query purpose, explicit target SHA and acquisition/receipt provenance. A changed org base, query purpose, target, mapped identity or qualified feature receipt/binding invalidates the old pass; promotion must reacquire/requalify the actual exact-bound combination. A workspace pass cannot prove that old X contains a later org hotfix. An isolated negative control makes workspace ancestry pass while promotion ancestry against old X fails; neither the command nor owner silently selects the newer fork tip.

Post-sync AC1 binds immutable promotion merge M, the protected sync PR/qualified merge identity and retained trusted merge receipt, reobserved org/main and resulting fork/main, and an ancestry witness for M plus the current org tip. Exact-map/target/observation provenance and changed-tip/base requalification remain required. Root defines a consumable decision contract; it does not fabricate trusted receipts or perform the externally owned merge.

## Proposed pure decision/input boundary

Default practical placement is a new portable root `.cljc` law namespace, with effects in the existing NBB project adapter. The exact namespace/signature/result schema are review decisions. Inputs must bind source path, mapped org/fork/network identities, observed 40-hex org/fork tips, parent lists, acquisition completeness/boundaries and associated provenance. Supply time if freshness is modeled; the law reads no clock, filesystem, Git/API, environment or native provider object. SDK/native values are normalized and validated at the outer edge. Reuse compatible owning shape contracts where already available; do not copy a child runtime or add a ledger/board authority.

Proposed distinctions:

- Equal valid tips for the correctly identified pair pass; a valid graph witness from fork tip to org tip proves ancestor/behind and passes. Validate every observed witness edge/identity. A verified positive path need not require irrelevant older branches to be complete.
- Drift is a negative conclusion permitted only when the complete valid ancestry closure relevant to fork tip excludes the observed valid org tip. Missing required parent objects, shallow cuts, absent/missing refs or unverified acquisition make the negative conclusion unknown. An untrusted `complete=true`, output row count or process exit 0 cannot certify graph completeness.
- Invalid endpoint/parent representations, duplicate conflicting commit definitions, cycles, wrong mapped repository/network, unexpected ref kinds, detached substituted SHAs, inconsistent/stale observations or an unsafe acquisition scope must terminate with a named refusal/unknown result, never pass or false drift. Decide invalid-vs-unknown taxonomy explicitly in review; both block promotion.
- Repetition, traversal order, equal retries, merge-parent order and irrelevant valid observations cannot change the result. Terminate cycle-safely and bound the acquisition adapter independently. The proof binds the exact observed pair/tips; changed tips need new acquisition and decision, not a reused green result.

Negative diagnostics include mapped repository names, available exact tips, a reason and non-destructive sync guidance. They must not include tokens, authorization headers, raw private endpoints, environment dumps or full unrelated Git history. Equality/ancestry does not grant issuer authority, fork membership, review approval or deployment admission.

## Proposed isolated acquisition and actual CLI contract

The future `nbb scripts/project.clj validate --remote` path first retains current structural/map checks, validates the flag contract and selects explicit mapped org/fork pairs. Observe the intended `main` refs from authoritative Git/remotes, preserving the actual repository/network context. A missing main ref, failed lookup, denied auth, nonzero Git exit, timeout, malformed output, changed ref or unavailable evidence is named unknown/refusal with nonzero exit. Do not silently check another branch, substitute local HEAD, infer that a repository was deleted, or equate a transport failure with drift. Validate provider/Git output before the pure decision.

Acquire into a newly allocated private store for each repository pair/attempt, with bounded fetch/deepen toward the exact observed org SHA or supported complete-history comparison. The acquisition path must not depend on primary/submodule checkout dirt, mutate configured remotes/branches/indexes/objects of another lane, invoke Git hooks/credential prompts unexpectedly, or reuse a writable shared cache/store. Keep command arguments separate from shell text; guard options/ref identities. Verify all needed objects/parents and record shallow/completeness limits. Failed deepening is unknown, not a false complete root. A paired concurrent-run fixture proves no writes/ref changes escape one run and that one run cannot clean up the other's store.

Recheck relevant tips at the actual before-promote boundary. If changed during acquisition/qualification, refuse or reacquire under reviewed bounded policy; do not promote using stale pass. The Foresight adapter only emits data/diagnostics and exit status. It neither performs post-promotion sync nor decides trusted purpose/merge admission. The external consumer must reject unknown/invalid/drift/nonzero/missing/wrong-pair/stale results and pass only an appropriately qualified exact-bound record. No new local reviewer, promotion gate-policy engine or board parser is introduced.

For AC1, the external owner proof starts with org promotion merge M, opens/merges a protected sync PR for the full observed org SHA, verifies the resulting fork tip contains M, and runs the actual root check. If a later org commit is observed, checking M alone cannot assert the fresh org tip is synchronized. Upstream-sync purpose remains terminal and must not re-trigger staging/promotion. Fictional fixtures prove decision/interface behavior; actual owner-admitted operational evidence is separately required before claiming the full post-promotion outcome.
